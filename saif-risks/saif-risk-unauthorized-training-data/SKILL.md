# SAIF Risk: Unauthorized Training Data (UTD)

## Risk Overview

**Who can mitigate:** Model Creators

**Description:** Training a model using data that is not authorized to be used for that model.

A model trained or fine tuned on unauthorized data could pose legal or ethical challenges. Unauthorized Training Data may include any data that violates policies, contracts, or regulations. Examples are user data that does not have appropriate user consent, unlicensed copyrighted data, or legally restricted data.

## When Risk is Introduced

Unauthorized Training Data is introduced early in development if not properly filtered out during:
- Data ingestion
- Data processing
- Model evaluation during training

## When Risk is Exposed

The risk is exposed during:
- **Development:** Through data filtering and processing steps or training, tuning, and evaluation
- **Model use:** When the model may produce inferences based on data it shouldn't have access to

## Mitigation Controls

| Control | Implementation |
|---------|---------------|
| **Training Data Sanitization** | Detect and remove unauthorized data before training |
| **Training Data Management** | Ensure all data used to train and evaluate models is authorized for intended purposes |

## Real-World Examples

- **2023 Spotify incident:** Spotify removed multiple AI-generated tracks that were generated by a model trained on unlicensed data

## Testing Checklist

- [ ] Audit all training data sources for proper licensing
- [ ] Verify user consent for all user data used in training
- [ ] Check for copyrighted material in training datasets
- [ ] Implement automated data provenance tracking
- [ ] Review data sharing agreements and contracts
- [ ] Test model outputs for signs of unauthorized data influence
